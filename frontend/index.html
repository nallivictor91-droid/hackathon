Full-Stack Architecture: Frontend, Backend & Supabase

How responsibilities and .env secrets are differentiated across layers

Presentation Layer

💻 Frontend (Browser)

/frontend/ • frontend/.env

  • UI Components & Glassmorphism
  • Reads window.__ENV from /env.js
  • Markdown rendering & syntax highlighting
  • Local UI state & SSE chunk reception
  • ✅ Safe Public Key: SUPABASE_ANON_KEY
  • ❌ Never holds the secret GEMINI_API_KEY
Server Gateway

🛡️ Backend (Node.js)

/backend/ • backend/.env

  • Express.js HTTP & SSE Server (Port 3000)
  • Loads GEMINI_API_KEY securely from .env
  • Loads SUPABASE_SERVICE_ROLE_KEY / ANON_KEY
  • Persists prompts & responses to Supabase
  • ✅ API keys kept strictly server-side
Database Layer

🗄️ Supabase (PostgreSQL)

supabase.co (Cloud SQL)

  • Stores conversation history in public.messages
  • Groups chats by session_id in public.sessions
  • Row-Level Security (RLS) protection
  • Persists conversations across browser reloads
AI Intelligence

✨ Google Gemini LLM

generativelanguage.googleapis.com

  • Processes conversation history + latest prompt
  • High-speed neural generation (Gemini 1.5/2.5)
  • Streams tokens in real time back to backend

Environment Variables Separation

Environment File Variables Included Security Level Purpose
backend/.env PORT, GEMINI_API_KEY, SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY Strictly Private Loaded only by Node.js server to authorize Gemini and Supabase database requests.
frontend/.env SUPABASE_URL, SUPABASE_ANON_KEY, BACKEND_API_URL, GEMINI_DEFAULT_MODEL Public / Safe Client configuration served dynamically via /env.js to initialize browser-side features.
